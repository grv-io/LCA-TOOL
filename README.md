# DhatuChakra (धातुचक्र)

**AI-driven Life Cycle Assessment & circularity engine for Indian metals.**
*हर टन का हिसाब — every tonne, accounted for.*

Built for **Smart India Hackathon · Problem Statement #48** (AI-Driven LCA Tool for Advancing Circularity and Sustainability in Metallurgy and Mining, Ministry of Mines).

📄 **[Technical documentation (PDF)](docs/DhatuChakra_Documentation.pdf)** — full methodology, formulas, validation and data sources.

---

## The problem

A proper Life Cycle Assessment tells a metal plant its environmental cost per tonne — but today it needs **25+ process parameters**, commercial databases (≈ €4,000/yr), and weeks of consultants. Most Indian plants simply skip it, right when circular-economy policy and the EU's **CBAM** carbon border tax (phasing in from 2026) make these numbers essential.

## What DhatuChakra does

Give it **5–8 inputs — or one plain sentence** like *"aluminium smelter in Odisha, about 40% scrap, mostly coal grid"* — and it returns:

- **Impacts per tonne, cradle-to-gate:** global warming (CO₂e), energy, water, acidification
- **Real uncertainty:** every result carries a p05–p95 range from a 1,000-run Monte Carlo simulation
- **Circularity score:** the Material Circularity Indicator (Ellen MacArthur methodology), rendered as a 24-spoke chakra gauge
- **AI-estimated parameters:** a k-nearest-neighbours model fills missing values *with an honest confidence score* — estimates are always flagged and overridable
- **India-first grid model:** clickable state map with indicative grid intensities (Himachal 0.18 → Chhattisgarh 0.92 kg CO₂/kWh)
- **CBAM export-cost calculator:** carbon cost in ₹ crore per the EU phase-in schedule (Reg. 2023/956)
- **Decision support:** linear-vs-circular comparison with live sliders, India/world benchmarks, recommendations that cite your own numbers, and an ISO-14044-style printable report
- **Hindi / English** interface toggle

Everything runs **fully client-side and offline** — no backend, no accounts, no external services.

## Validated numbers

The engine is pinned to an expected-output table; all presets sit inside published ranges:

| Route (India grid) | Ours (t CO₂e/t) | Published range |
|---|---|---|
| Aluminium — primary | **16.6** | 16–20 (IAI) |
| Aluminium — recycled | **0.92** | 0.5–1.5 (IAI) |
| Steel — BF-BOF | **2.19** | 1.9–2.4 (worldsteel) |
| Steel — EAF (scrap) | **0.70** | 0.4–1.0 (worldsteel) |
| Copper — primary | **4.24** | ≈4.2 (EF 3.1, indicative) |

Hand-check (Al primary): `14,500 kWh × 0.71 kg CO₂/kWh + 6,300 kg = 16,595 kg ≈ 16.6 t`. The recycled-aluminium route is **94% lower** — the shift this tool is built to drive.

## How it works

```
User input (5 fields / one sentence)
        │
        ▼
Text parser ──► k-NN imputer (500 physics-generated scenarios, real confidence)
        │
        ▼
LCA engine  ◄── factor library (IAI · worldsteel · CEA · EF 3.1 · IDEMAT — every factor cited)
        │
        ▼
Monte Carlo (1,000 runs) ──► results + MCI + benchmarks + CBAM ₹ + recommendations + report
```

- `prototype/js/data.js` — every constant, factor and preset (single source of truth)
- `prototype/js/calc.js` — impact formulas, MCI, Monte Carlo, k-NN, recommendations, parser
- `prototype/js/ml_data.js` — training rows generated by `prototype/scripts/make_training_data.js`
- `prototype/DATA_SPEC.md` — the full data contract: formulas, factors, expected outputs
- `prototype/DESIGN.md` / `prototype/SCREENS.md` — design system and screen specifications

## Data sources (all public, all free)

CEA CO₂ Baseline Database v19 · International Aluminium Institute LCI · worldsteel LCI methodology · EU EF 3.1 / ELCD · IDEMAT 2024 (TU Delft) · Ellen MacArthur Foundation MCI v3 · Regulation (EU) 2023/956. Zero database licensing cost; the in-app provenance table links every figure to its source.

## Honest limitations

The prototype uses a factor-based engine with fixed water/acidification ratios — right for route comparison, not site permitting. State grid factors and copper values are indicative and labelled as such. The k-NN model is trained on physics-generated data and demonstrates the imputation architecture, not field accuracy. Full limitations and the production roadmap (Brightway2.5 matrix LCA, quantile-gradient-boosting imputer, LLM parser, FastAPI + PostgreSQL) are in the [technical documentation](docs/DhatuChakra_Documentation.pdf).
